# know-your-harness

让 harness 认识它的主人。跟 [star-your-harness](../star-your-harness/) 是前后手：star 搭出空的 `about-me/`，这个把它填上，而且用的是数据，不靠用户自己写自我介绍。

## 铁律

**1. 数字只能来自脚本。**
画像里出现的每一个数字（粉丝、浏览、篇数、倍数）都必须能在 `rank.py` 或 `collect.py` 的输出里找到。算不出来的量不写。

**2. 每条结论都要带依据。**
「你的教程类内容表现好」这种话不许单独出现。必须写成「表现最好的 10 条里有 6 条是教程（第 1、2、4、5、7、9 条）」。数据撑不住的结论删掉。

**3. 密钥只碰名字，不碰值。**
`probe.py` 只列环境变量名。不要去读 `.env` 或 shell 配置里等号右边的内容，不要把值写进任何文件或回复。

**4. 只读用户自己的账号和公开数据。花钱的调用先报价。**
按量计费的接口，调用前告诉用户预计几次、多少钱，等他点头。

**5. 不替用户发任何东西。**
这个 Skill 全程只读。

## 流程

### 第一步：探测

```bash
python3 ~/.claude/skills/know-your-harness/scripts/probe.py -o probe.json
```

输出三样：哪些工具可用、哪些装了但要重新登录、环境里有哪些像密钥的变量名。内置清单只有最常见的几个，用户有别的工具时写一个 JSON 用 `--tools` 追加（格式见脚本开头）。

把结果讲给用户听，然后问一个问题：**「你主要在哪几个平台发内容？给我主页链接或账号名。」** 脚本认不出的工具（各种平台的数据 API、自己写的脚本）让他补充调用方式。

### 第二步：采集

零成本的两类直接跑：

```bash
python3 ~/.claude/skills/know-your-harness/scripts/collect.py <harness目录> -o <harness>/<数据目录>
```

- `github`：自己的仓库和 star
- `local`：harness 里写过多少文本，按目录和月份分布

其他平台由你按用户给的工具去拉，**每个平台存一个原始 JSON 到同一个数据目录**，文件名 `MMDD-平台-posts.json`。常见做法：

| 平台 | 怎么拉 |
|------|--------|
| 有命令行工具的平台（X、GitHub、YouTube 等） | 用户装了对应 CLI 就直接调，输出存成 JSON |
| 只有后台的平台（公众号、小红书、Newsletter、博客等） | 后台导出的 CSV 或 Excel 转成 JSON，或者用户自己有的数据 API |
| 都没有 | 跳过，在画像里写「未接通」 |

每个人的平台组合不一样，这里不预设。用户说了哪几个就拉哪几个。

拉不到的不要硬凑。画像里如实写哪些接通了、哪些没有。

数据目录建议放在复盘层（`50-protocols/data/` 或类似位置）。原始数据通常不该推到 GitHub，提醒用户在 `.gitignore` 里排除，或者用 sync-your-harness 处理。

### 第三步：排名

每个平台的 JSON 跑一次：

```bash
python3 ~/.claude/skills/know-your-harness/scripts/rank.py <数据目录>/1111-x-posts.json -o <数据目录>/1111-x-rank.json
```

脚本不认平台，只认结构：自动找到内容数组、标题字段、指标字段、时间字段，认得「1.2万」这种写法，默认剔除转发。识别错了用 `--metric` 和 `--title` 指定。

输出：合计、平均、中位数、最高是中位数的几倍、前 10% 内容拿走了多少比例、每月条数、最好和最差各 N 条。

### 第四步：写画像

读完所有 rank 输出之后，在 `about-me/` 下写 `动态画像.md`。结构固定：

```markdown
# 动态画像
> 生成日期：YYYY-MM-DD。数据来源和时间范围见各节。下次刷新建议在一个月后。

## 一句话
（从数据里看，这个人是谁。不超过两句）

## 各平台现状
| 平台 | 账号 | 条数 | 主指标合计 | 中位数 | 最高 | 状态 |

## 什么内容表现好
（3 到 5 条规律。每条后面括号注明依据的是哪几条内容）

## 什么内容表现差
（同上）

## 写作和表达习惯
（从表现最好的内容里读出来的：长度、开头方式、有没有第一人称）

## 数据没接通的部分
（哪些平台没拉到，缺什么）
```

### 第五步：回填 TOOLS.md 和 NOW.md

- 把 `probe.py` 打印的表格贴进 `TOOLS.md` 的「连接状态」，补上用户告诉你的平台工具、账号和成本
- 如果 `NOW.md` 的主线还空着，根据画像给一个建议，**让用户自己确认后再写进去**

### 第六步：交代刷新方式

告诉用户：画像会过期。建议每月重跑一次第二到第四步，旧的数据文件不删，新的按日期另存，这样能看出变化。

## 几个容易做错的地方

**别拿一条爆款当规律。** 脚本会告诉你最高那条是中位数的多少倍。倍数很大时，去掉第一名再看剩下的。

**别把转发算成用户的表现。** `rank.py` 默认剔了，但有的平台没有转发标记，看到明显是别人的内容要手动排除并说明。

**样本太少就直说。** 不到 20 条的平台只列数据，不归纳规律。

**别替用户下定位。** 画像描述的是「数据显示什么」，「你应该做什么」留给用户和 NOW.md。

## 文件

```
know-your-harness/
├── SKILL.md
└── scripts/
    ├── probe.py     探测可用工具和数据源，只读变量名
    ├── collect.py   拉 GitHub 仓库 + 统计本地文本
    └── rank.py      任意平台 JSON → 最好 / 最差 / 分布
```
